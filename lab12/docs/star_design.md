# Проєктування зіркової схеми OLAP-куба (Результат 1)

## 1. Бізнес-процес та зерно факту
- **Сектор та тематична область:** Енергетика - Моделювання енергомереж (ОЕС України).
- **Бізнес-процес:** Оперативно-диспетчерський моніторинг перетоків потужності, технологічних втрат, спрацювань релейного захисту (РЗА) та каскадних ризиків на магістральних підстанціях 750/330/110 кВ за даними SCADA/EMS.
- **Зерно факту (`fact_grid_telemetry`):** Один агрегований погодинний запис телеметрії та диспетчерських подій для конкретної одиниці обладнання на визначеній підстанції за фіксованого стану режиму та погодних умов (1 рядок = 1 одиниця обладнання x 1 година спостереження).

## 2. Ключові бізнес-питання (8 аналітичних питань)
1. **BQ-1 (Ієрархічний баланс втрат - ROLLUP):** Який сумарний обсяг переданої електроенергії та технологічних втрат за енергетичними районами і класами напруги з проміжними підсумками та загальним підсумком по ОЕС України?
2. **BQ-2 (Багатовимірна аварійність - CUBE):** Як розподіляються тривалість аварійних простоїв та кількість спрацювань РЗА одночасно за класами таксономії обладнання, категоріями подій та всіма їхніми комбінаціями?
3. **BQ-3 (Піковий зимовий режим - Slice):** Яке середнє активне навантаження та доступний резерв потужності N-1 на магістральних підстанціях під час вечірніх пікових годин зимового сезону?
4. **BQ-4 (Аварійний підкуб - Dice):** Які втрати енергії та індекс ризику спостерігаються на об'єктах 750 кВ і 330 кВ Західного та Центрального регіонів під час коротких замикань і перевантажень за високого ризику ожеледі?
5. **BQ-5 (Сезонна матриця перетоків - PIVOT):** Як змінюється квартальний обсяг передачі електроенергії (Q1-Q4) у розрізі чотирьох синхронних енергетичних районів?
6. **BQ-6 (Динаміка та ковзне середнє - Window Cumulative):** Яка помісячна кумулятивна передача енергії та 3-місячне ковзне середнє технологічних втрат у кожному енергорайоні?
7. **BQ-7 (Ранжування вузьких місць - Window Rank):** Які топ-3 одиниці обладнання у кожному класі таксономії мають найвищий піковий коефіцієнт завантаження та найбільшу частоту спрацювань РЗА?
8. **BQ-8 (Деталізація за таксономією - Taxonomy Drill-down):** Як деталізуються технологічні втрати, простої та індекс ризику при переході вниз по ієрархії таксономії від верхнього класу (`GridComponent`) до підкласу (`PowerTransformer`, `OverheadLine`, `DistanceProtection`) та конкретного апарата з IRI?

## 3. Специфікація вимірів та таксономії з IRI
| Таблиця виміру | Первинний ключ | Ієрархія (рівні деталізації) | Політика SCD | Опис та роль таксономії |
| :--- | :--- | :--- | :--- | :--- |
| `dim_date` | `date_key` | `year -> quarter -> month -> full_date -> hour` | Статичний довідник | Календарна сітка погодинних інтервалів та маркерів пікового навантаження. |
| `dim_taxonomy_equipment` | `taxonomy_key` | `class_level1_name -> subclass_level2_name -> equipment_name` | **SCD Тип 2** (`effective_from`, `effective_to`, `is_current`) | Вимір таксономії з ЛР 5/6. Кожен елемент має глобальний `taxonomy_iri` та `parent_iri` у просторі `http://www.semanticweb.org/ontologies/2026/power-grid#`. |
| `dim_substation` | `substation_key` | `region_cluster -> oblast -> substation_name` | **SCD Тип 1** (перезапис) | Топологічна прив'язка до 4 синхронних районів (Західний, Центральний, Дніпровський, Південний) та класів напруги 750/330/110 кВ. |
| `dim_event_type` | `event_type_key` | `event_category -> event_subclass` | **SCD Тип 1** (перезапис) | Класифікатор диспетчерських режимів та аварійних подій із прив'язкою до IRI класів подій (`ShortCircuit`, `OverloadCondition`, `CascadingFailureEvent`). |
| `dim_weather` | `weather_key` | `icing_risk_level -> wind_speed_group -> condition_name` | Статичний довідник | Метеорологічні умови проходження максимуму навантаження (ожеледь, гроза, штормовий вітер). |

## 4. Класифікація мір таблиці фактів (`fact_grid_telemetry`)
| Міра | Тип даних | Одиниця | Клас адитивності | Правило агрегації у кубі |
| :--- | :--- | :--- | :--- | :--- |
| `energy_transmitted_mwh` | `DOUBLE` | МВт·год | **Адитивна** | Підсумовується (`SUM`) за всіма вимірами куба без обмежень. |
| `tech_losses_mwh` | `DOUBLE` | МВт·год | **Адитивна** | Підсумовується (`SUM`) за часом, підстанціями та таксономією. |
| `outage_duration_min` | `DOUBLE` | хв | **Адитивна** | Підсумовується (`SUM`) для розрахунку сумарного простою та індексу SAIDI. |
| `protection_trips_count` | `INTEGER` | од. | **Адитивна** | Підсумовується (`SUM`) для обліку частоти спрацювань РЗА. |
| `active_load_mw` | `DOUBLE` | МВт | **Напівадитивна** | Сумується по лініях/трансформаторах у момент часу, але за часом береться `AVG` або `MAX`. |
| `available_reserve_mw` | `DOUBLE` | МВт | **Напівадитивна** | Сумується по вузлах на зріз часу; вздовж осі часу агрегується через `AVG` або `MIN`. |
| `load_factor_pct` | `DOUBLE` | % | **Неадитивна** | Відносна величина завантаження; обчислюється через `AVG` або відношення сум. |
| `voltage_level_kv` | `DOUBLE` | кВ | **Неадитивна** | Фізичний потенціал шин; агрегується виключно через `AVG`, `MIN`, `MAX`. |
| `risk_score` | `DOUBLE` | 0..1 | **Неадитивна** | Індекс ризику каскадної відмови; агрегується через `AVG` або `MAX`. |
