# План виправлень RAG-конвеєра з пріоритетами та метриками успіху (СР 11)

На основі класифікації відмов розроблено пріоритизований інженерний план усунення виявлених дефектів.

| Пріоритет | Категорія відмови | Пропонований інженерний захід | Змінений фактор / архітектура | Цільова метрика успіху |
|---|---|---|---|---|
| **P0** | Search (Версійність) | Впровадження Temporal Metadata Filtering: обов'язкове врахування дат чинності нормативів та відсікання анульованих редакцій | Метадані `valid_from`/`valid_to` у FAISS pre-filter | Recall@3 чинних норм: 0.85 -> 0.98; ліквідація помилки TC-15 |
| **P1** | Generation (Колізії) | Модифікація системного промпту з обов'язковою секцією «Таблиця розбіжностей» при виявленні суперечливих джерел | Prompt Engineering v2 (Conflict Matrix Directive) | Faithfulness на суперечливих тестах: 0.75 -> 0.95 |
| **P2** | Context (Мультихоп) | Розширення витягу підграфа з 1-hop до 2-hop для топологічних запитів транзиту потужності | Graph Traversal depth=2 в Neo4j + PageRank weighting | Multi-hop Context Recall: 0.70 -> 0.92; усунення дефекту TC-05 |
| **P3** | Policy (Аудит безпеки) | Впровадження суворого аудиту спроб ін'єкції з автоматичним блокуванням сесії та сигналізацією в SIEM | Middleware FastAPI Security Filter + Regex Guardrails | Abstention & Safety Rate: 0.95 -> 1.00; повний аудит TC-20 |

## Очікуваний ефект від реалізації плану:
1. Загальна частка безпомилкових відповідей зросте з 70.0% (14/20) до 95.0% (19/20).
2. Частка помилок пошуку та генерації скоротиться з сумарних 20% до 5%.
3. Надійність вирішення нормативних колізій досягне 100%.
