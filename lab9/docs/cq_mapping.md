## 1. Специфікація міток (Labels) та типів зв'язків (Relationships)

Створена графова схема Property Graph (LPG) містить **10 міток вузлів** та **9 типів зв'язків**, що повністю покриває потреби моделювання топології та надійності енергосистеми.

### Мітки вузлів (Labels):
1. `:PowerPlant` — генеруючі потужності (ГЕС, АЕС, ТЕС, СЕС, ВЕС).
2. `:Substation` — магістральні та розподільчі вузлові підстанції (750 кВ, 330 кВ, 110 кВ).
3. `:TransmissionLine` — повітряні та кабельні лінії електропередач.
4. `:Transformer` — блочні та автотрансформатори перетворення класів напруги.
5. `:CircuitBreaker` — комутаційні вимикачі з контролем струму.
6. `:RelayProtection` — мікропроцесорні комплекти захисту (ДЗ, ДЗЛ, ДЗТ).
7. `:SCADA_System` — цифрові системи диспетчерського керування та збору даних.
8. `:ConsumerNode` — промислові та міські вузли споживання електричної енергії.
9. `:GridEvent` — експлуатаційні події, короткі замикання та каскадні аварії.
10. `:Operator` — системний оператор магістральних мереж (НЕК Укренерго).

### Типи зв'язків та атрибути походження (Provenance):
Всі зв'язки графа містять метадані походження та валідності:
- `source`: первинне джерело фіксації факту (диспетчерський журнал, паспорт обладнання, телеметрія SCADA).
- `confidence`: рівень достовірності від 0.0 до 1.0 (за замовчуванням 0.98–1.0).
- `validFrom`: дата набуття чинності факту у схемі (наприклад, `2026-01-01`).

Перелік зв'язків:
1. `[:SUPPLIES_POWER_TO]` — від електростанції до вузлової підстанції чи лінії.
2. `[:CONNECTS_TO]` — фізичне приєднання лінії електропередач до шин підстанції.
3. `[:CONTAINS_EQUIPMENT]` — розміщення трансформаторів та вимикачів на підстанції.
4. `[:PROTECTS]` — зона дії та захист елементів комплектом реле.
5. `[:TRIPS_BREAKER]` — команда на аварійне розмикання вимикача.
6. `[:MONITORED_BY]` — передача телесигналізації та телеметрії до SCADA.
7. `[:FEEDS_CONSUMER]` — передача електроенергії споживачам.
8. `[:TRIGGERS_EVENT]` — ланцюг причинно-наслідкової ескалації аварійних ситуацій.
9. `[:MANAGED_BY]` — підпорядкування об'єкта диспетчерському управлінню оператора.

## 2. Відображення компетентнісних питань (CQ1–CQ8) на шаблони Cypher

| № CQ | Формулювання компетентнісного питання | Шаблон Cypher-шляху |
| :---: | :--- | :--- |
| **CQ1** | Які магістральні підстанції досяжні від атомних станцій через ланцюги передачі потужності до 4 стрибків? | \`(p:PowerPlant {type: 'Nuclear'})-[:SUPPLIES_POWER_TO\|CONNECTS_TO*1..4]-(s:Substation)\` |
| **CQ2** | Який найкоротший фізичний маршрут передачі потужності від Дніпровської ГЕС до Львівської агломерації? | \`shortestPath((src:PowerPlant {id: 'DniproHPP'})-[:SUPPLIES_POWER_TO\|CONNECTS_TO\|FEEDS_CONSUMER*]-(dst:ConsumerNode {id: 'Consumer_Lviv_Metropolis'}))\` |
| **CQ3** | Яка сумарна встановлена потужність генерації за типами електростанцій та середня одинична потужність? | \`(p:PowerPlant)\` з подальшим \`RETURN p.type, sum(p.capacityMW), avg(p.capacityMW)\` |
| **CQ4** | Які лінії та підстанції напругою від 330 кВ містять у назві або розташуванні ключові слова західного та київського регіонів? | \`(n) WHERE (n:Substation OR n:TransmissionLine) AND n.voltageKV >= 330.0 AND n.name =~ '(?i).*(Західн\|Київ\|Львів).*'\` |
| **CQ5** | Які підстанції мають встановлені автотрансформатори та які вимикачі чи комплекти захисту з ними пов'язані? | \`(s:Substation)-[:CONTAINS_EQUIPMENT]->(t:Transformer)\` з опційними \`OPTIONAL MATCH (s)-[:CONTAINS_EQUIPMENT]->(cb:CircuitBreaker)\` та \`OPTIONAL MATCH (rp:RelayProtection)-[:PROTECTS]->(t)\` |
| **CQ6** | Які 5 найпотужніших ліній електропередач та які кінцеві споживачі живляться від суміжних підстанцій? | \`(l:TransmissionLine) WITH l ORDER BY l.capacityMW DESC LIMIT 5 MATCH (l)-[:CONNECTS_TO]->(s:Substation)-[:FEEDS_CONSUMER]->(c:ConsumerNode)\` |
| **CQ7** | Які лінії, проміжні підстанції та кінцеві споживачі опиняться під загрозою знеструмлення у разі аварійного відключення ПС 750 кВ Західноукраїнська? | \`(root:Substation {id: 'SS_Zakhidna'})-[:CONNECTS_TO\|FEEDS_CONSUMER*1..4]-(downstream)\` |
| **CQ8** | Який повний ланцюг ескалації аварійних подій ініціюється коротким замиканням на лінії 750 кВ та які критичні ризики фіксуються на кожному кроці? | \`(origin:GridEvent {id: 'EV_ShortCircuit_Line750_ZK'})-[:TRIGGERS_EVENT*1..5]->(cascade:GridEvent)\` |

## 3. Порівняльна таблиця трансформації моделі: Онтологія (OWL/RDF) $\rightarrow$ Граф властивостей (LPG/Neo4j)

| Елемент онтології (ЛР 7–8) | Реалізація у Property Graph (ЛР 9) | Тип трансформації | Обґрунтування інженерного рішення |
| :--- | :--- | :--- | :--- |
| **Ієрархія класів** \`pg:PowerPlant\`, \`pg:HydroPowerPlant\`, \`pg:NuclearPowerPlant\` | Вузол з міткою \`:PowerPlant\` та атрибутом \`type: 'Hydro'\` / \`'Nuclear'\` | Класи $\rightarrow$ Мітки + Атрибути | Спрощує схему, усуваючи надмірну фрагментацію класів у графовій базі та прискорюючи фільтрацію за індексом. |
| **Клас ліній** \`pg:TransmissionLine\`, \`pg:OverheadLine\`, \`pg:CableLine\` | Вузол з міткою \`:TransmissionLine\` та властивістю \`type: 'OverheadLine'\` | Класи $\rightarrow$ Мітки | Зберігає єдиний контекст електричних ліній із можливістю групування кабельних та повітряних ділянок. |
| **Об'єктна властивість** \`pg:suppliesPowerTo\` | Спрямоване ребро \`[:SUPPLIES_POWER_TO]\` з властивостями \`{source, confidence, validFrom}\` | Object Property $\rightarrow$ Relationship + Edge Properties | Ребра у Neo4j є повноцінними об'єктами з атрибутами походження, що в RDF вимагало б складної реіфікації. |
| **Об'єктні властивості зв'язку** \`pg:connectedTo\`, \`pg:containsEquipment\` | Спрямовані ребра \`[:CONNECTS_TO]\` та \`[:CONTAINS_EQUIPMENT]\` | Object Property $\rightarrow$ Relationships | Дозволяє нативну побудову маршрутів у Cypher через шаблони \`()-[]->()\`. |
| **Датні властивості** \`pg:hasNominalVoltageKV\`, \`pg:hasRatedCapacityMW\` | Властивості вузлів \`voltageKV\`, \`capacityMW\` числових типів Float | Datatype Property $\rightarrow$ Node Properties | Уможливлює створення прямих B-Tree індексів та діапазонних фільтрів без потреби конвертації типів \`xsd:float\`. |
| **Словник ризиків** \`skos:Concept\` | Вузли з міткою \`:GridEvent\` та властивістю \`riskScore\` | Словникові поняття $\rightarrow$ Вузли подій | Дозволяє безпосередньо обчислювати каскадні ланцюги через зв'язки \`[:TRIGGERS_EVENT]\` без допоміжних триплетів. |
| **Організація** `schema:Organization` | Вузол з міткою `:Operator` | Зовнішній клас $\rightarrow$ Окремий вузол | Зберігає семантику системного диспетчера без зовнішніх URL-залежностей. |
